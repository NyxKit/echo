# Desktop delivery decision

Decision recorded before implementation, 2026-10-07.

The first packages target Linux x86-64 (glibc, a graphical session, Secret Service) and Windows 11 x86-64. Bundle Node 24.21.0, production dependencies including the matching Sharp binaries, built Vue assets, and a small C host helper. Ordinary installations do not require Node or pnpm. Linux delivery is a tar.gz with an explicit per-user installer and desktop entry; Windows delivery is a per-user NSIS installer. Neither installer enables login startup by default or removes the library during application updates/uninstall.

Linux runtime baseline audit, 2026-10-09: validate the actual tarball on clean Ubuntu 22.04 and 24.04 userspaces before declaring a minimum tested distribution baseline. Run as an unprivileged user with networking disabled, a read-only package, disposable writable state and no host home, desktop bus or credentials. Exercise bundled Node/SQLite/Sharp, native helper loading, the installer/recovery checks and the private D-Bus controller contract. Build the test images from official Ubuntu images and distribution packages using an empty build context. Both checks now pass for the current tarball: Ubuntu 22.04.5 with glibc 2.35 and Ubuntu 24.04.4 with glibc 2.39. Ubuntu 22.04 is the minimum tested Linux userspace baseline; do not infer compatibility with older systems or other distributions solely from glibc version. Rerun this gate when the compiler, native dependencies or bundled runtime changes. These checks establish userspace compatibility only; a container shares the host kernel and cannot prove desktop-shell, login-session, default-browser or keyring-prompt integration.

The Linux tray implements StatusNotifierItem and the D-Bus menu protocol with GLib/GIO, avoiding a dependency on the obsolete GTK AppIndicator implementation. Desktops need a StatusNotifier host (GNOME typically needs its tray extension). An unavailable tray leaves browser Open/Quit and command-line controls usable. The Windows tray uses Shell_NotifyIcon and a native popup menu. Tray helpers exchange only bounded lifecycle commands and public status text with a Node controller; no library records or provider credentials enter the tray. A separate per-user tray lease prevents duplicate icons. The controller polls authenticated server status, preserves the icon after a crash, and offers restart; it never resends analysis. The desktop entry starts and opens the service before attempting to create the tray, so an absent helper or unavailable session bus cannot prevent browser use. Startup failure still supplies a public error category to the tray for retry and returns a failing exit status.

Login startup is an explicit tray checkbox. Linux uses a user XDG autostart entry; Windows uses the current-user Run registry key. Login launch opens no browser. The Windows helper also provides an OS-held exclusive lock, default-browser opening, private DACL checks, and Credential Manager storage. Generic credential blobs have a 2560-byte limit, so the bounded connection record uses 2000-byte chunks under a random generation with a final manifest switch; previous generations are removed afterward. Credentials pass only over anonymous pipes, never command arguments or logs.

Linux credential correction, 2026-10-09: [secret-tool's stdin reader](https://github.com/GNOME/libsecret/blob/main/tool/secret-tool.c) is limited to 8192 bytes. Echo must store connection records as base64 parts of at most 6000 characters in Secret Service, with a bounded manifest containing the byte length and SHA-256. Two fixed slots bound abandoned partial writes; writes fill and verify the inactive slot before switching the root manifest, then clear the old slot. Existing single-entry JSON records remain readable and migrate on the next write. The complete record is limited to 100,000 UTF-8 bytes, matching the Windows adapter. Serialize operations under the existing service lease and retain the previous committed record when staging fails. Distinguish locked items from absent records with a private search when lookup returns no value, so a locked keyring cannot appear disconnected. Never delete a newly published slot on an ambiguous root-write outcome. All parts remain in the OS credential store, including after restart; no credential files or application database storage are introduced. Validate with simulated interruptions and an isolated real Secret Service containing only generated records.

Windows managed directories use protected user/SYSTEM/Administrators DACLs and reject reparse points and unexpected ownership. Node POSIX mode bits are not evidence of Windows access control. Linux retains owner-only files and flock leases.

Linux installation audit, 2026-10-09: include an installed `uninstall.sh` using the bundled runtime. It stops the authenticated instance before removing application files, the matching command link/desktop entry and that installation's login entry. Preserve library/state/credentials and unrelated files or launchers. Installation must reject a nonempty unmarked target and foreign command/desktop entries before replacing anything; a missing marker inside an existing directory is not proof that the destination is unused. Exercise those cases, uninstall and reinstall with disposable prefixes and a generated library. The installer uses its own authenticated control code instead of executing the target installation’s runtime: an interrupted update or uninstall may already have removed the target runtime/server files. Recovery from an intact extracted package must remain possible in that state.

macOS packaging is deferred: this environment has no macOS host for Keychain, login-item, Safari, notarization, and installer validation. That would add a third credential adapter, tray implementation, signing workflow, and unverified release platform. Safari/WebKit compatibility remains a UI requirement and is tested where tooling permits.

## Release evidence

Implementation, compiler checks, synthetic protocol tests, and artifact inspection are tracked separately from desktop acceptance. Public release requires actual Linux and Windows installation, tray, login startup, credential-store, repeated-launch, shutdown, and browser checks. Windows signing requires the release publisher's certificate and identity. No certificate, existing keyring, real browser profile, or real provider account may be inspected by development tooling.

Current compiler, browser, capacity, controller and package results are in [release acceptance](library-release-acceptance.md), together with the target-desktop checklist. The Linux controller contract is exercised on an isolated D-Bus session; Windows binaries and the NSIS installer build successfully but have not been run on Windows.
